# Curation methodology

Version 0.1.0 organizes normalized historical evidence and source metadata into four standalone tables. The release includes no application code, database schema, pipeline, or rebuild dependency. Future maintenance can edit the CSV and schema files directly after checking the original public sources.

The input review covered 122 event records, evidence records, event/source relationships, and source provenance metadata. The action evidence contained 476 unique factual records and 619 rows across crosswalk relationships, where one action could appear more than once. The release selected the 395 unique action records whose source URL is on an official website with a reviewed reuse declaration, whose curation flag says no personal information, and whose source title, publisher, retrieval time, and original URL are available. It did not copy source wording or original documents. The selected records cover 76 events.

Event IDs were assigned once in chronological order to selected, source-supported identities. The release found no duplicate named typhoon and year among selected events. Names and aliases were deduplicated within each event. Source versions were deduplicated by original URL and source snapshot hash, reducing 92 upstream source-version identities to 88 physical source rows; observation rows retain their specific `source_version`. No two selected observations had the same source, locator, action type, state, location, and factual attributes. Possible cross-publisher event equivalences outside this release were not guessed.

Event date windows use included report dates in Taiwan local time. If included reports differ, the event row spans the earliest reported start and latest reported end, while observation-level time remains separate. A calendar-day value is encoded as a date, not midnight. Empty values and unsupported locations remain empty. Administrative areas mentioned by observations are listed as reported areas, not promoted into exact affected geometry.

The selected facts include road status, evacuation, shelter operation, field and pump deployment, emergency-response activation, repair, rescue, warnings, and similar actions. `attributes_json` carries source-supported counts and qualifiers. The category is a factual response record, not an assessment of effectiveness or urgency. A recorded order is not proof of completion; action sequence is not converted to priority.

One source reported 207 pumps across four named counties, while the earlier normalized record attached that aggregate to one candidate county. The public row keeps the four-county aggregate at event precision and removes the candidate field. Two road-segment rows carried the same four-location aggregate closure count; that count was omitted from the segment rows because it cannot be assigned to either segment. Their independently reported road states remain. This avoids false county or segment precision and double counting.

The following were intentionally excluded: raw PDF and HTML payloads; internal Evidence Release bundles; 81 action records from sites without a qualified reuse basis in this pass; all 87 NCDR aggregate outcome observations pending separate rights review; 46 event records without an included action observation; remote-sensing and flood geometries; 298 candidate feature rows; 429 retrospective target rows; 10 pairwise weak-signal rows; ranking labels, model outputs, train/test splits, and 20 m spatial indices. Exclusion is a publication and scope decision, not a claim that the facts are false or that an action did not occur.

The release does not attempt to reconstruct source prose, re-download changing webpages, or infer a negative observation from silence. Corrections should name the affected `TWD-` ID, source URL, source locator, evidence change, and release version. Existing IDs should remain fixed even when a correction changes a name or date.

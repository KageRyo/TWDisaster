# Curation methodology

Version 0.1.1 organizes normalized historical evidence and source metadata into four standalone tables. The release includes no application code, database schema, pipeline, or rebuild dependency. Future maintenance can edit the CSV and schema files directly after checking the original public sources.

The input review covered 122 event records, evidence records, event/source relationships, and source provenance metadata. The action evidence contained 476 unique factual records and 619 rows across crosswalk relationships, where one action could appear more than once. The release selected the 395 unique action records whose source URL is on an official website with a reviewed reuse declaration, whose curation flag says no personal information, and whose source title, publisher, retrieval time, and original URL are available. It did not copy source wording or original documents. The selected records cover 76 events.

Event IDs were assigned once in chronological order to selected, source-supported identities. The release found no duplicate named typhoon and year among selected events. Names and aliases were deduplicated within each event. Source versions were deduplicated by original URL and source snapshot hash, reducing 92 upstream source-version identities to 88 physical source rows; observation rows retain their specific `source_version`. No two selected observations had the same source, locator, action type, state, location, and factual attributes. Possible cross-publisher event equivalences outside this release were not guessed.

Event date windows use included report dates in Taiwan local time. If included reports differ, the event row spans the earliest reported start and latest reported end, while observation-level time remains separate. A calendar-day value is encoded as a date, not midnight. Empty values and unsupported locations remain empty. Administrative areas mentioned by observations are listed as reported areas, not promoted into exact affected geometry. Observations are included only when supported by the cited sources; a missing observation means no qualifying record was included, not that the action did not occur.

The selected facts include road status, evacuation, shelter operation, field and pump deployment, emergency-response activation, repair, rescue, warnings, and similar actions. `attributes_json` carries source-supported counts and qualifiers. The category is a factual response record, not an assessment of effectiveness or urgency. A recorded order is not proof of completion, and the records do not assess whether an action was effective or urgent.

One source reported 207 pumps across four named counties, but an earlier draft assigned that total to one county without source support. The public row retains the count at event precision and does not assign it to an individual county. Two road-segment rows carried the same four-location aggregate closure count; that count was omitted from the segment rows because it cannot be assigned to either segment. Their independently reported road states remain. This avoids false county or segment precision and double counting.

This release includes action records supported by official public sources with a reviewed reuse statement and available provenance. It does not redistribute raw source documents. Sources without a qualified reuse basis, aggregate outcomes pending separate rights review, and events without an included action observation remain outside this release. These boundaries reflect source coverage and publication scope; they do not imply that excluded events or actions did not occur.

The release does not attempt to reconstruct source prose, re-download changing webpages, or infer unreported actions. Corrections should name the affected `TWD-` ID, source URL, source locator, evidence change, and release version. Existing IDs should remain fixed even when a correction changes a name or date.
